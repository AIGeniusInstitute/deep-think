# DeepThink v1.0.10 发布说明

> 自托管的多用户本地 AI Agent Loop Engineering 系统（支持桌面端 + 浏览器 + 移动端）
> Powered By AI Genius Institute，AI 光剑

发布日期：2026-07-25

v1.0.10 是一个**引擎扩展 + 执行稳定性 + 协作可视化**版本。本版本接入 **pi 作为第四 Agent 执行引擎**（并完成协议核心 v2 重写），新增 **Agent Reminder 机制**防止长任务目标偏离，**修复 Agent 执行层稳定性**（卡 running / 容器睡眠 / trace 不持久化），并完成 **TeamPage 执行视图增强 v2**。

## ✨ 新功能

### pi 引擎：第四 Agent 执行引擎

将 pi（v0.82.0）作为 DeepThink 的第四 Agent 执行引擎接入主聊天对话流，参考现有 atomcode / codex / opencode 的实现模式。

- **RPC 长驻接入**：pi 以 `pi --mode rpc` 接入——长驻 stdio JSONL 协议，专为进程集成设计。一次 spawn 后多 turn 通过 stdin prompt 命令续聊，相比 codex 的 per-turn spawn 避免冷启动开销，pi session 原生续接。是首个 stdio JSONL 长驻 adapter（codex 为 per-turn spawn JSONL，opencode 为长驻 HTTP+SSE）。（`f200e95`）
- **协议核心 v2 重写（二进制 RPC 子进程方式）**：删除 `node:readline`，新增 `attachJsonlReader`（LF-only）修 pi RPC 协议违规；新增 `PiRpcDriver`（单例 stdout reader + id 关联响应分发 + turnHandler）消除双重 readline 抢流；新增 `message_end` 错误捕获（assistant stopReason=error 时透传 status:error）；新增 `writePiModelsJson` 从 DeepThink `PiConfig.providers` 生成 `models.json` 写入隔离 `PI_CODING_AGENT_DIR`，支持自定义 baseURL（如 DashScope `/apps/anthropic`），apiKey 用 `$ENV` 引用不落盘——用户无需在本机配置 pi。（`d9884fb`）
- **配置面板**：前端新建 `PiEngineSection.tsx` 设置面板；EngineSwitcher / EnginesPage / SettingsNav / SettingsPage / stores-chat 加 pi 选项；后端 `GET/PUT/POST /api/config/pi` + `testPiRpc` 连通性测试。

首版限制（PRD §3.1）：不桥接 DeepThink 内置 MCP；跨引擎会话不连续；仅宿主机模式；provider 未覆盖回退 `--api-key`；图片输入不支持。详见 `docs/test_report/pi-engine/`。

### Agent Reminder 机制

在 Agent 执行长任务时周期性 / 事件驱动地重新注入任务目标，防止上下文遗忘与目标偏离。注入日志与实时状态在对话右侧 Reminder 面板显式呈现，默认开启，用户可在「设置 → 个人偏好」关闭。

- **F1 ReminderEngine**：agent-runner `for-await` 循环内按 `tool_result` 步数计数周期注入 + PreCompact hook 压缩后事件驱动注入，经 `MessageStream.push` 注入 user message（与 IPC follow-up 同通道，不改 system prompt）。
- **F2 流式事件**：`shared/stream-event.ts` 新增 `reminder_injected` 类型与 reminder payload，`make sync-types` 同步三处副本。
- **F3 宿主配置**：`ContainerInput.reminderConfig` 透传，`runtime-config` `reminder.json`（默认 interval 8），`buildReminderConfig` 解析用户开关。
- **F4 前端面板**：`chat.ts` StreamingState 新增 `reminderLog` / `reminderStatus` / `toolStepsSinceReminder`，新建 `ReminderPanel` 组件挂入 ChatView 右侧栏 `SIDEBAR_TABS`（桌面 + 移动），服务端 snapshot 恢复 `reminderLog`。
- **F5 用户开关**：镜像 `default_require_mention` 全链路（ProfileSection → auth → schemas → routes → db → types），`users.reminder_enabled` 默认 1。

测试：单元 5/5、UI 自动化 9/10 实测 + TC-07 构建验证，全量 `make build` 与三端 tsc 通过。详见 `docs/test_report/reminder-mechanism/TEST_REPORT.md`。

## 🐛 缺陷修复

### Agent 执行层稳定性（三层根因同源修复）

证据：`messages.db` `graph_runs` 16 failed / 0 completed；`trace_tool_calls` 1589 行全 `graph_run_id=NULL` / `tool_name=unknown`（web:main 的 graph run 0 行）。详见 `docs/issues/2026-07-25-agent-exec-stability.md`。

1. **trace 不持久化**：graph-runner stream 回调漏调 `persistTraceNodeFromStreamEvent`（IM 路径 `index.ts:3678` 有、graph 路径遗漏）。补接线，并补 stream-processor `tool_use_start` 的 `toolInput` 字段（此前 `input_json` 永空）。
2. **agent 卡 running（pre-result 卡死）**：agent-runner `for-await` 在 SDK 握手后无 event 时永久阻塞，无 in-query watchdog。新增 `INACTIVITY_TIMEOUT_MS=10min` 活体 watchdog，仅对 graph 运行（`graphRunId` 非空）启用，触发后 interrupt + emit error + 退出，避免 IM 人机交互误杀。
3. **成功结果后容器睡眠（post-result 卡死）**：graph 路径 host 从不写 `_close` / `_drain` sentinel，agent-runner 查询完成后进入 `waitForIpcMessage` 永久阻塞至 30min `containerTimeout`。graph 单次运行模式：`graphRunId` 非空时 query 收尾后直接 `break` 退出，不进入 `waitForIpcMessage`。
4. **`runAgentNode` 假完成**：丢弃 `runAgent` 返回值、恒返回 completed，容器超时 / 错误也假完成。改为检查 `ContainerOutput.status`，`error` / `closed` → `failed`。

验证：三端 tsc + `make build`（agent-runner exit 0）；单测 16 文件 161/161 通过（含 super-agent-team-trace 8/8）。（`bfc2d0d`）

### settings tab=pi 静默回退 claude

`SettingsPage.tsx` 的 `VALID_TABS` / `SYSTEM_TABS` / `mobileTabs` 三处白名单遗漏了 `'pi'`，导致 `?tab=pi` 不命中 `VALID_TABS` 而回退 `defaultTab='claude'`，渲染成 `ClaudeProviderSection`（标题「模型服务商」），pi 引擎配置页（启用开关 / `binaryPath` / `cliScriptPath` / Provider）无法显示。补 `'pi'` 到三处，与 atomcode / codex / opencode 同形同位置。详见 `docs/issues/2026-07-25-pi-settings-tab-missing.json`。（`c49cc6c`）
