1. 范围与目标

修复 PG 模式（DATABASE_URL=postgresql://）下 initDatabase() 启动即崩的 4 个缺口，使云端多 Pod 水平扩缩容端到端可启动：
  • G1 FTS5 虚拟表 + 触发器在 PG 非法语法 → 启动崩溃
  • G2 知识库搜索用 MATCH/snippet()/bm25() FTS5 专有函数
  • G3 sqlite-vec 在 PG 模式尝试 loadExtension 抛错噪声
  • G4 pg_trgm 扩展未初始化，KB 搜索无 GIN 索引

5. 已知限制（留待后续 Phase）

  • ⚠ token_usage 分析查询（28 处 json_extract/json_each/json_type）在 PG 模式报错 — 仅影响 dashboard 统计端点，核心对话/Agent/记忆热路径不受影响（JSON 列以文本存取）。字符串正则翻译易破坏正常查询，风险/收益不合理，留待后续 Phase 用 PG 原生 jsonb 重写。
  • ⚠ pgvector ANN 向量索引未接线 — postgres.yaml 已用 pgvector/pgvector:pg16 镜像，但代码端向量查询 PG 下走线性扫描（可用但非 ANN）。
  • ⚠ 真实云端 K8s 集群部署验证未做 — 本地 kind 集群已验证多写并发；端到端云部署需云厂商凭证。

6. 结论

PG 模式启动阻塞缺口（G1-G4）已全部修复，SQLite 默认行为零回归（111 测试通过），后端 tsc 零错误。 PG 模式现可完成 initDatabase() 全 schema 初始化并支持知识库全文搜索（pg_trgm）与向量搜索（线性降级）， 云端多 Pod 水平扩缩容端到端可启动。剩余分析端点 json 兼容与 pgvector ANN 为后续 Phase 显式延期项。
