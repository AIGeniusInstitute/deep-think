# 镜像构建 403 / 外网下载慢 + traceNode 类型滞后

`make start-prod PORT=9999` 在 CN 网络下镜像构建失败、后端编译失败的修复记录。

## 1. 用户现象

执行 `make start-prod PORT=9999` 无法启动。表现：

- Docker 构建卡在 `ghcr.io/astral-sh/uv:latest` 层，下载 23MB 用时 280s+ 仍不完成；
- 或 `apt-get install` 步骤大面积 `403 Forbidden` 后 `exit code: 100`；
- 或 `pip install headroom-ai` 步骤 `403 Forbidden` 后整层失败；
- 镜像反复重建无法产出，`make start-prod` 退到 `_ensure-docker-image` 阶段即报错退出；
- 即便镜像构建通过，后端 `_build-backend-if-stale` 的 `tsc` 报 `TS2339: Property 'traceId' does not exist ...`，启动仍失败。

## 2. 问题描述

容器镜像构建（`container/Dockerfile`、`container/sandbox/Dockerfile`）在 CN 网络下多个外网资源拉取失败或极慢，外加一处类型真相源滞后导致的编译错误，共 5 个阻断点：

1. **apt 镜像 IPv6 403**：`APT_MIRROR=mirrors.tuna.tsinghua.edu.cn`，清华镜像 IPv6 节点对 debian pool 大量 `.deb` 返回 403（IPv4 节点正常 200）。buildkit 在 `--network=host` 下优先走 IPv6，于是 `apt-get install` 整层 abort exit 100。
2. **pip 镜像对 headroom-ai 403**：`PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`，清华源对 `headroom-ai` 包返回 403（未同步/过滤），`pip install "headroom-ai[code,mcp]~=0.27.0"` 直接失败。
3. **ghcr.io uv 镜像慢**：`COPY --from=ghcr.io/astral-sh/uv:latest`，ghcr.io 在 CN 裸网络下拉取极慢（280s/23MB）。
4. **沙箱 Dockerfile 无国内源**：`container/sandbox/Dockerfile` 的 apt 直连 `deb.debian.org`、pip 直连 `pypi.org`，CN 网络下前者超时、后者极慢（numpy/matplotlib 等 15s+/包）。
5. **traceNode 类型滞后**：`shared/stream-event.ts`（真相源）的 `traceNode` 类型只有 6 个粗 nodeType 且缺 v57 字段（`traceId`/`spanId`/`parentSpanId`/`evidence`/`outputRef`），但 `src/chat-trace-persist.ts` 访问这些字段、`container/agent-runner/src/trace-node-allocator.ts` 的 `TraceNodeDescriptor` 产生原子 nodeType（`thinking`/`compact`/`memory_recall`/...）。agent-runner 副本此前已含完整类型（编译通过），但真相源滞后，`make sync-types` 一旦同步会破坏副本；后端 `tsc` 也报 TS2339。

## 3. 根因

```bash
# 1. 清华 apt 镜像 IPv6 403 / IPv4 200
$ curl -4 -o /dev/null -w "%{http_code}\n" http://mirrors.tuna.tsinghua.edu.cn/debian/pool/main/p/python3.11/python3.11-dev_3.11.2-6%2bdeb12u8_amd64.deb
200
$ curl -6 -o /dev/null -w "%{http_code}\n" http://mirrors.tuna.tsinghua.edu.cn/debian/pool/main/p/python3.11/python3.11-dev_3.11.2-6%2bdeb12u8_amd64.deb
403

# 2. 清华 pip 源对 headroom-ai 403 / 阿里云 200
$ curl -o /dev/null -w "%{http_code} %{time_total}s\n" https://pypi.tuna.tsinghua.edu.cn/simple/headroom-ai/
403 0.29s
$ curl -o /dev/null -w "%{http_code} %{time_total}s\n" https://mirrors.aliyun.com/pypi/simple/headroom-ai/
200 0.11s

# 3. 替代 apt 源测速（中科大最快，IPv4+IPv6 均 200）
$ for h in mirrors.ustc.edu.cn mirrors.aliyun.com mirrors.cloud.tencent.com; do
    curl -o /dev/null -w "$h %{http_code} %{time_total}s\n" http://$h/debian/pool/main/p/python3.11/python3.11-dev_3.11.2-6%2bdeb12u8_amd64.deb
  done
mirrors.ustc.edu.cn 200 0.73s
mirrors.aliyun.com 200 2.08s
mirrors.cloud.tencent.com 302 0.07s

# 5. 真相源滞后于副本（agent-runner 副本含完整类型，shared 不含）
$ grep -c "traceId\|spanId\|parentSpanId" shared/stream-event.ts   # 0（修复前）
$ grep -c "traceId\|spanId\|parentSpanId" container/agent-runner/src/stream-event.types.ts  # >0
```

依据：
- 清华大学 TUNA 镜像 IPv6 节点对部分路径返回 403，是已知的 CDN/路由层行为；IPv4 不受影响。
- buildkit `--network=host` 复用宿主 DNS/协议栈，getaddrinfo 在双栈机器上优先 AAAA → 命中 IPv6 403。
- `headroom-ai` 是 PyPI Beta 包，清华镜像未同步该包名 → 403；阿里云已同步。

## 4. 复现路径

1. 确保 `deepthink-agent:latest` 镜像不存在或 sentinel 失效（`rm -f .docker-build-sentinel`）。
2. 在 CN 网络下（裸网络，无代理）执行 `make start-prod PORT=9999`。
3. 观察到 `_ensure-docker-image` → `./container/build.sh` 在 apt 层或 headroom 层 abort，或 uv 层卡住数分钟。
4. 即便手动 `./container/build.sh` 产出镜像，`_build-backend-if-stale` 的 `tsc` 仍报 `chat-trace-persist.ts` 的 TS2339。

## 5. 诊断方法

```bash
# 测各 apt 镜像对 debian pool 的可达性（注意 IPv4 vs IPv6）
PKG=python3.11/python3.11-dev_3.11.2-6%2bdeb12u8_amd64.deb
for h in mirrors.tuna.tsinghua.edu.cn mirrors.ustc.edu.cn mirrors.aliyun.com; do
  curl -s -o /dev/null -w "$h %{http_code} %{time_total}s\n" http://$h/debian/pool/main/p/$PKG
done

# 测 pip 镜像对 headroom-ai 的可达性
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://pypi.tuna.tsinghua.edu.cn/simple/headroom-ai/
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://mirrors.aliyun.com/pypi/simple/headroom-ai/

# 真相源与副本是否一致
diff shared/stream-event.ts src/stream-event.types.ts && echo "一致" || echo "不一致→需 sync"

# 构建日志关键词
grep -nE "403|Forbidden|did not complete|TS2339|headroom, version|uv 0\.|Build complete" <buildlog>
```

## 6. 修复方案

### 6.1 `container/Dockerfile`

```diff
-ARG APT_MIRROR=mirrors.tuna.tsinghua.edu.cn
+ARG APT_MIRROR=mirrors.ustc.edu.cn
```
```diff
-COPY --from=ghcr.io/astral-sh/uv:latest /uv /usr/local/bin/uv
-COPY --from=ghcr.io/astral-sh/uv:latest /uvx /usr/local/bin/uvx
+RUN pip install --break-system-packages \
+      --index-url https://mirrors.aliyun.com/pypi/simple/ uv \
+    && uv --version \
+    && command -v uvx
```
```diff
-ARG PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
+ARG PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
```

选型理由：uv 是独立二进制，`pip install uv`（阿里云）秒级安装且自带 `uv`/`uvx` entry，无需拉 ghcr 镜像；uv 在容器内未被 entrypoint/agent-runner 使用，仅作为可选工具存在，改 pip 安装零行为影响。

### 6.2 `container/build.sh`

```diff
-APT_MIRROR="${APT_MIRROR-mirrors.tuna.tsinghua.edu.cn}"
+APT_MIRROR="${APT_MIRROR-mirrors.ustc.edu.cn}"
-PIP_INDEX_URL="${PIP_INDEX_URL:-https://pypi.tuna.tsinghua.edu.cn/simple}"
+PIP_INDEX_URL="${PIP_INDEX_URL:-https://mirrors.aliyun.com/pypi/simple/}"
```

> 注意 `build.sh` 用 `${VAR:-default}` / `${VAR-default}` 总会传 `--build-arg`，会覆盖 Dockerfile ARG 默认值，故 build.sh 默认值必须同步改。

### 6.3 `container/sandbox/Dockerfile`

加 `APT_MIRROR`(ustc) + sed 替换、pip `--index-url` 阿里云，与主 Dockerfile 一致。

### 6.4 `shared/stream-event.ts`（真相源）

`traceNode` 补全：nodeType 扩展为粗 6 + 原子 9 联合（与 `TraceNodeDescriptor` 对齐），新增 `traceId`/`spanId`/`parentSpanId`/`evidence`/`outputRef`。`evidence` 内联等价结构（避免 shared import db 类型导致跨项目复制后路径失效）。改后 `make sync-types` 同步到三处副本（`src/`、`web/src/`、`container/agent-runner/src/`），三项目 `typecheck` 全 exit 0。

### 6.5 验证

- `make typecheck-backend` / `typecheck-agent-runner` / `typecheck-web` 均 exit 0；
- `./container/build.sh` 全程通过：`apt(ustc)` → `uv 0.12.9(阿里云)` → `headroom 0.27.0(阿里云)` → `feishu-cli(gitcode,15s)` → `agent-runner npm run build` → `Build complete!`；
- `make start-prod PORT=9999` 后台守护启动，`GET /api/health` → `{"status":"healthy","checks":{"database":true,"queue":true}}`。

## 7. 处理卡住的状态

排查过程中遇到若干卡死状态，处理如下：

- **残留 docker build 进程**：多次失败构建留下 `Tl`(stopped) 状态的 `docker build` / `buildx` 进程，互相争抢 buildkit 锁。`kill -9 <pid>` 清理后让正确构建独占。
- **buildkit 层缓存命中但 ARG 变了**：改 `APT_MIRROR`/`PIP_INDEX_URL` ARG 值后，从该层起失效重跑（预期）；`CACHEBUST` 导致 npm install 层每次重跑（预期，npmmirror 秒级）。
- **`node_modules/node_modules` 嵌套损坏**：`/home/me/deepthink/node_modules` 下存在嵌套 `node_modules/node_modules/`，`npm install` rename acorn 报 ENOENT。`rm -rf node_modules && npm install --registry=https://registry.npmmirror.com --allow-git=all` 重装解决（603 packages in 6s）。
- **`/tmp/claude-1000/.../tasks` 文件系统 ENOSPC**：后台 task `.output` 堆积 + 构建日志撑满 `/tmp`，导致 Bash 工具无法执行。`rm -f` 旧 `.output` 与 `/tmp/dt-*.log` 释放。
- **`oh-my-zsh` 安装 skipped**：`raw.githubusercontent.com` 可达（200）但 install.sh 内部 `git clone github.com` 在 CN 裸网络下超时；Dockerfile 已有 `timeout -k 5 90 ... || echo skipped` 兜底，cosmetic 主题，不影响运行。
- **工作目录消失**：session 期间 `/home/me/prod/deepthink`（环境 primary working dir）整体消失（非命令所致、非挂载点、bash_history 无记录），最初在那应用的修复丢失。按用户确认改在 `~/deepthink`（主源码，CLAUDE.md 指定位置）重新应用全部修复。

## 8. 经验沉淀 / 预防

- **镜像源选型**：apt 用中科大（IPv4+IPv6 双栈 200，~0.5s/文件）；pip 用阿里云（对 `headroom-ai` 等 Beta 包 200，~0.1s）。清华镜像的 IPv6 403 与 Beta 包 403 是两个独立坑，今后新加包/源前先 `curl` 验证可达性。
- **build.sh 与 Dockerfile ARG 默认值必须同步**：build.sh 用 `${VAR:-default}` 总会传 `--build-arg`，覆盖 Dockerfile ARG 默认。改镜像源时两处都改。
- **真相源与副本一致性**：`shared/stream-event.ts` 是真相源，`make sync-types` 同步到三处副本。新增字段时先改真相源再 sync，避免副本先行、真相源滞后的不一致（本仓库此前 agent-runner 副本先行导致 typecheck 通过但真相源滞后，sync 即破坏副本）。`make typecheck` 会通过 `scripts/check-stream-event-sync.sh` 校验一致性。
- **可选工具走 pip 而非镜像 COPY**：uv 这类独立二进制工具，优先 `pip install`（国内镜像秒级），避免 `COPY --from=ghcr.io/...` 拉取境外镜像仓库。
- **巡检脚本建议**：CI/本地加一个 `scripts/check-mirrors.sh`，对依赖的 apt/pip/docker registry 源做 HEAD 探测，任一 403/超时即告警，避免构建时才发现。
- **磁盘水位**：构建镜像 4GB+，多次失败会堆积 buildkit 缓存与日志撑满 `/tmp`；定期 `docker builder prune` 与清理 `/tmp/dt-*.log`。
