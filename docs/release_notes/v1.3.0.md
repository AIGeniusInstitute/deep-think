# DeepThink v1.3.0 发布说明

> 自托管的多用户本地 AI Agent Loop Engineering 系统（支持桌面端 + 浏览器 + 移动端）
> Powered By AI Genius Institute，AI 光剑

发布日期：2026-09-06

v1.3.0 是一个**云原生与协作**版本——DeepThink 从 v1.2.0「单机多智能体编排 + 对外开放服务」跃迁到「**K8s 全量无状态化 + 横向多 Pod 扩缩容 + 多人协作工作 + 平台能力深化**」的新阶段。本版本的主轴是**把单机状态栈整体搬迁到云原生分布式基座**：经 K8s 云端部署（Phase 1）→ 真正横向多 Pod 无状态化（Redis 事件总线 + 分布式选主 + PostgreSQL 同步桥）→ Agent IPC Redis 消息驱动 + Agent Runner 独立 Service → Phase 3 云端生产化（pgvector / 对象存储 / Litestream 灾备）→ 全量无状态化缺口审计闭环。在云原生主轴之外，本版本同时交付 **多人协作工作能力（3 模式 + 群共享工作区）**、**平台能力深化（全过程 Trace / 校验节点 / 测试评测 / Skills 版本管理）**、**企业级工具治理与最小权限基线**、**一级导航简化** 与 **PG 时间戳溢出修复 + 本机持久化存储栈**。

---

## ✨ 新功能

### 一、云原生：从单机到 K8s 全量无状态化与水平扩缩容

v1.3.0 最大的工程命题——把单机状态栈（SQLite 文件 + 本地 IPC 文件 + 进程内队列）整体改造为可在 K8s 多 Pod 间水平扩缩的云原生基座，跨越 5 个阶段闭环：

#### 1. K8s 云端部署与数据持久化改造（Phase 1，`k8s-cloud-deploy`）

把 DeepThink 从「裸机 / Docker Compose」搬到 K8s，并解决无状态化首关的数据持久化问题：

- K8s 部署清单（Deployment / Service / Ingress / ConfigMap / Secret）+ 持久卷策略，Pod 无本地状态依赖。
- 云端部署数据持久化与并发 4 缺口补齐（`eec7333`）、首修 3 项遗留缺陷（trace 读端 / 备份 `pg_dump` / 多租户 workspace，`2b1d669`）。
- 云部署 UI 自动化测试报告 26 项全通过（`46a5627`）。

#### 2. 真正横向多 Pod 无状态化（`full-horizontal-scaling`）

让多个 Pod 真正并行、对等、可独立调度，而非单实例 + 热备：

- **Redis 事件总线**：跨 Pod 消息广播，替代单机进程内队列。
- **分布式选主**（IM 通道 leader 选举）：同一 IM 配置在同一时刻只由一个 Pod 持有连接，避免重复消费 / 重复回复。
- **PostgreSQL 同步桥**：把 SQLite 单机状态镜像到 PG，跨 Pod 共享会话 / 任务 / 审计状态。

#### 3. Agent IPC Redis 消息驱动 + Agent Runner 独立 Service（`agent-ipc-redis`）

把 Agent 主进程 ↔ Agent Runner 的 IPC 从「本地文件 watch」改造为「Redis 消息驱动」，使 Agent Runner 可作为独立 K8s Service 部署、跨 Pod 通信：

- Agent IPC Redis 消息驱动 + Agent Runner 独立 Service（`05cd2aa`）。
- 分布式 IPC 遗留三项闭环（`c77ae9a`）：mcp-bridge Redis 输出 / Web 端 ipc-out 订阅 / 分布式 Runner 长驻循环。

#### 4. Phase 3 云端生产化（`k8s-phase3-completion`）

把单机依赖的向量库 / 对象存储 / 备份灾备替换为云原生生产级组件：

- **pgvector** 替代 Milvus（嵌入式向量化，与 PG 同库，少一个独立服务）。
- **对象存储（MinIO/S3）** 替代本地文件挂载存放产物 / 下载。
- **Litestream** 持续备份 SQLite WAL 到对象存储（灾备 / 跨 Pod 恢复）。
- pg-sync-driver 同步桥死锁修复 + MinIO / agent-runner 接线（`b2d1e08`）、同步桥剩余 2 缺口（Int32Array 视图 + rows 守卫，`eb2315a`）。

#### 5. 全量无状态化缺口审计闭环（`k8s-stateless-completion`）

对全链路做收尾审计，分两层补齐剩余缺口：

- **Tier A — PG 数据层三大致命缺口**（`5e95a73`）：`INSERT OR REPLACE` 真 upsert、`lastInsertRowid`、`date(localtime)`，确保翻译层忠实 SQLite 语义。
- **Tier B — 水平扩缩容三大功能性阻塞**（`66b9410`）：IM leader 选举、Claude 引擎 Redis IPC、周期任务门控。
- Tier B 分布式原语真实 Redis 验证脚本 11/11 PASS（`2ca9b1e`）；收尾审计 2 处未闭环缺陷 + task_state 校准（`c40b63c`）。
- 全量无状态化缺口修复 PRD / 技术方案 / 任务状态 / HTML 测试报告（`ca51d10`）。

#### 6. 接线共享并发计数器（`k8s-concurrency-wire`）

多 Pod 计费并发上限跨 Pod 生效——把单机 `MAX_CONCURRENT_*` 计数器接到 Redis 共享计数器，使「每用户 / 全局并发上限」在水平扩缩后仍准确（`02be3a3`），并补修 2 处未闭环缺陷（`5e20185`）。

#### 7. PG 模式启动阻塞修复（`k8s-pg-compat`）

PG 模式端到端启动链路 8 项兼容性修复（`ab0f7a4`）：FTS5 / sqlite-vec 后端分支 + `pg_trgm` 搜索，让 PG 后端能真正拉起。

### 二、多人协作工作能力建设（`multi-user-collaboration`）

在既有 graph 编排底盘上新增「协作」维度，支持三种工作模式 + 群共享工作区：

- **编排者–工作者**（orchestrator-worker，向后兼容 legacy 串行链）。
- **对等模式**（peer，并行 agent + 文件扇入 shellCheck gate）。
- **批评对抗**（critic-adversarial，producer + 对抗 critic gate 回退循环）。
- **群共享工作区**：`collaborations/{collabId}/` 下落盘 `deliverables/` / `manifest/` / `final-deliverable/` / `shared-memory`，群成员经 `canAccessCollaboration` 授权共享读写，**不修改 `isUserOwnedFolder` 安全边界**。
- 零侵入 graph-engineering 核心：三种模式均以 `agent + gate` 节点表达，复用 gate-rollback 机制（gate 读 `upstreamNodeId` 输出，失败重跑上游）。
- 后端：`db.ts`（collaborations 表，schema 58→59）、`collaboration-builder.ts`、`routes/collaborations.ts`、`team-prompt.ts`（mode 感知提示词 + fallback）、`team-builder.ts`（单行接入）。
- 前端：`CollaborationPage` + collaborations store + 导航「协作」项。
- 验证：16/16 单测通过；3 场景集成组建成功，共享产物 / 记忆 API 验证通过。

### 四、企业级工具治理与最小权限基线（`tool-governance-least-privilege`）

对照腾讯 WorkBuddy / 豆包工作 / 千问 Work / Claude Cowork / Codex Harness 的 8 层架构审计后，落地「工具是风险边界」理念，新增 5 项最小权限能力：

1. **副作用分级**（read / write / admin）：HTTP method 自动推断 + 显式覆盖，贯穿 DB 列、API 响应、前端徽标。
2. **写操作幂等键**：`Idempotency-Key` 头 + SQLite 缓存，同 key 写操作命中回放，失败不缓存可重试；read 工具不缓存。
3. **调用审计**：`tool_call_audit_log` 表，记录 user / tool / side / `args_hash`（sha256 前 16 位，不含明文）/ http_status / result_status / request_id。
4. **滑动窗口限流**：per-user + per-tool + per-sideEffect，read=120 / write=30 / admin=10 per 60s，MCP 入口 429 + `Retry-After`。
5. **凭据加密**：AES-256-GCM 加密 `authHeader.value` 与 registry token，token 用 sha256 hash 比对（避免对加密列等值查询），v60 迁移幂等回写。

关键决策：`db.ts` 内联 AES（读 `DATA_DIR/config/claude-provider.key`），切断 `db→runtime-config` 静态链，避免 39 个 mock-config 既有测试受牵连；`crypto.ts` 保留静态 import 供 `engine.ts`。二者密文格式 `enc:v1:` 互操作。

验证：单元 20/20 + smoke 10 文件 122/122 零回归 + 后端 / 前端 tsc 零错 + e2e API（建工具 → sideEffect → 加密落库 → 幂等回放 → 审计 → 限流 429）全链路。

### 六、PG 时间戳溢出修复 + 本机持久化存储栈（`pg-timestamp-overflow + local-storage-stack`）

- **INTEGER→BIGINT 时间戳溢出修复**：PG 模式启动 autonomy-registry 把毫秒时间戳（如 `1788544038590`）插入 INTEGER 列，PG integer 4 字节溢出（22003）；SQLite INTEGER 是 8 字节不报。翻译器此前只映射 `INTEGER PRIMARY KEY→BIGSERIAL`，普通 INTEGER 未处理。`translateCreateTable` 与 ALTER ADD COLUMN 路径统一 INTEGER→BIGINT，忠实 SQLite 64 位语义，所有 ms 时间戳列不再溢出。
- **本机持久化存储栈**（`deploy/local/`）：`docker-compose.yml`（PG + pgvector / Redis AOF / MinIO S3，三 named volume）+ `.env.local-storage`（`DATABASE_URL` / `REDIS_URL` / `OBJECT_STORE_PROVIDER=s3` + `S3_*`）。文档说明 pgvector 替代 Milvus、`pg_trgm` 替代 ES 的架构选型。
- 验证（本机）：9999 启动零 ERROR / health 200 / setup+login 200 / 73 表 / autonomy 时间戳 bigint / Redis 连接 / MinIO bucket 就绪。

## 🐛 缺陷修复

- **镜像构建外网 403 / 慢源**：构建镜像拉取依赖时遭遇外网 403 与慢源，修复构建源 + `traceNode` 类型补全（`358fa81`）。
- **桌面版打包链根目录后端依赖缺失导致 tsc not found**：`desktop-pack-*` 链路根目录后端依赖未安装导致 `tsc not found`，修复打包链依赖装配（`5da187b`、`7b28c59`）。
- **`_ensure-native-abi` 探测失效导致 better-sqlite3 ABI 不匹配未被拦截**：修复原生 ABI 探测逻辑，避免带不匹配 native binding 的镜像流入运行态（`be7ab97`）。
- **start-prod 实例增加看门狗自动重启**：`stop-prod` 主动停止不重启，意外退出则看门狗自动拉起（`f7dc59a`）。
- **K8s 云端部署数据持久化与并发缺口**、**首修遗留缺陷**、**pg-sync-driver 同步桥死锁 / Int32Array 视图 / rows 守卫**、**PG 数据层 upsert / lastInsertRowid / date**、**水平扩缩容 IM leader / Claude 引擎 Redis IPC / 周期任务门控** 等详见上方云原生各阶段。
