架构总览

DeepThink 是自托管 AI Agent 工作站。三种部署形态，按规模递进：

形态适用数据库并发一键命令
本地 Node开发 / 单机个人SQLite单进程make setup
Docker 单机小团队 / 单机生产SQLite (卷持久化)单容器make docker-deploy
K8s 多副本企业云部署PostgreSQL多 Pod + Redismake k8s-deploy

组件关系：Web Server（Hono + Node）提供 HTTP/WebSocket API + 静态前端 → Agent Runner（独立进程/容器）执行 Claude Agent SDK 任务 → 沙箱容器执行不可信代码/浏览器。多副本下 Redis 做跨 Pod 事件总线 + 分布式选主 + Agent IPC，PostgreSQL 替代 SQLite。

一、本地源码部署（make setup）

最简形态，适合开发与单机使用。一键脚本幂等，可重复执行。

git clone git@gitcode.com:AIGeniusInstitute/deepthink.git ~/deepthink
cd ~/deepthink

# 一键：检查依赖→安装→编译→初始化→设admin→启动
make setup

# 或只装不启
make setup ARGS=--no-start

# 后台守护模式（隔离数据目录，断线不掉）
make setup ARGS=--prod PORT=9999

# 自定义管理员
ADMIN_NAME=alice ADMIN_PASS=Str0ng make setup

启动后访问 http://localhost:9898，默认管理员 admin/88888888（首次登录后请立即改密）。

make setup 做了什么（6 步） 
1. 检查 Node≥20 / git / npm（Docker 可选）
2. make install：npm install + 编译 agent-runner（走 npmmirror）
3. 初始化数据目录 ~/.deepthink/data（迁移仓库内旧 ./data）
4. make admin-set：设置/重置管理员（幂等）
5. 构建容器镜像（Docker 可用时）
6. 启动：前台 make start 或后台 make start-prod

手动分步（精细控制）

make install          # 装依赖 + 编译 agent-runner
make build            # 编译前后端（build:all）
make admin-set        # 设 admin 账号
make start            # 启动（pm2 注册过则 pm2 restart，否则前台阻塞）

# 隔离生产实例（不撞主实例）
make start-prod PORT=9999
make stop-prod PORT=9999
make status

二、Docker 单机部署（make docker-deploy）

容器化单机生产，数据持久化到 Docker 卷或宿主路径。

cd ~/deepthink

# 一键：生成密钥→构建镜像→启动→健康检查
make docker-deploy ARGS="--port 9999 --apikey sk-ant-xxx"

# 持久化到宿主路径（便于备份）
make docker-deploy ARGS="--port 9999 --apikey sk-ant-xxx --data-dir /opt/deepthink-data"

# 复用已构建镜像不重建
make docker-deploy ARGS="--no-build --port 9999"

# 手动 docker compose
docker compose -f deploy/docker/docker-compose.yml --env-file deploy/docker/.env up -d --build
注意：Docker 模式默认 SQLite 单容器，适合中小规模。如需多副本并发，请用 K8s 形态。

三、K8s 云部署（make k8s-deploy）

企业级多副本部署：Web Server 多 Pod + 独立 Agent Runner Deployment + Redis（事件总线/选主）+ PostgreSQL（pgvector）+ PVC + HPA。

cd ~/deepthink

# 1. 构建并推送镜像（远程集群需推仓库）
docker build -t deepthink-server:latest -f deploy/docker/Dockerfile.server .
# docker tag deepthink-server:latest <registry>/deepthink-server:latest && docker push ...

# 2. 一键部署
make k8s-deploy ARGS=" \
  --domain deepthink.yourcompany.com \
  --image registry.cn-hangzhou.aliyuncs.com/your/deepthink-server:latest \
  --apikey sk-ant-xxx \
  --pg-password YourStr0ngPgPass"

# 仅本机 kind 测试（无需域名/镜像仓库）
make k8s-deploy ARGS="--domain deepthink.local --apikey sk-ant-xxx"

脚本完成 4 件事：① 生成 Secret（随机 session/PG 密码，或 --secret-file 复用） ② sed 配置 Ingress 域名 + 镜像 ③ kubectl apply -k deploy/k8s/ ④ 等待 rollout 就绪 + 初始化 admin。

部署后验证

kubectl -n deepthink get pods,svc,hpa,ingress
kubectl -n deepthink rollout status deployment/deepthink-web

# 域名 DNS 生效前用端口转发
kubectl -n deepthink port-forward svc/deepthink 8080:9898
# → http://localhost:8080  默认 admin/88888888

# 健康端点
kubectl -n deepthink exec deploy/deepthink-web -- curl -s localhost:9898/health
kubectl -n deepthink exec deploy/deepthink-web -- curl -s localhost:9898/ready

扩缩容

# 或交给 HPA（CPU>70% 自动扩，2-20 Pod）
kubectl -n deepthink get hpa

kubectl delete namespace deepthink    # 一键删除全部资源
# PVC 数据需单独删：
kubectl delete pvc -n deepthink --all

配置管理

设计原则：所有运行时配置走 Web 界面（Setup 向导 + 设置页），API Key 经 AES-256-GCM 加密落盘，无需手编配置文件。环境变量仅用于部署拓扑（端口/数据目录/数据库连接/多副本协调）。

完整环境变量参考见仓库根 .env.example。关键变量：

变量默认说明
WEB_PORT9898HTTP 监听端口
DEEPTHINK_DATA_DIR~/.deepthink/data数据根目录（DB/配置/工作区/记忆）
WEB_SESSION_SECRET首启随机会话签名（多副本必须显式设置）
DATABASE_URL—（SQLite）设为 PG 连接串启用多副本
REDIS_URL—设为启用跨 Pod 事件总线（不设则 no-op 降级）
TRUST_PROXYfalse反向代理后设 true

备份与恢复

本地 / Docker

make backup                          # 打包 ~/.deepthink/data → deepthink-backup-{date}.tar.gz
make restore FILE=deepthink-backup-20260904-000000.tar.gz
# Docker：宿主路径模式直接 tar 该目录；named volume 用 docker run 备份卷

K8s（CronJob 自动 + 手动）

# 自动：backup-cronjob.yaml 每天 03:00 执行（PG→pg_dump|gzip，SQLite→cp），保留 7 份
# 手动触发一次：
kubectl -n deepthink create job --from=cronjob/deepthink-backup manual-backup-1

# 手动 PG 备份：
kubectl -n deepthink exec statefulset/postgres -- \
  pg_dump "$DATABASE_URL" | gzip > deepthink-pg-$(date +%F).sql.gz

# 恢复（PG）：
kubectl -n deepthink scale deployment/deepthink-web --replicas=0
gunzip -c deepthink-pg.sql.gz | kubectl -n deepthink exec -i statefulset/postgres -- psql "$DATABASE_URL"
kubectl -n deepthink scale deployment/deepthink-web --replicas=2
注意：备份含 session-secret.key 与 claude-provider.key 明文，妥善保管，勿提交 git。

升级与回滚

本地源码

cd ~/deepthink
git pull origin main
make install          # 依赖更新
make build            # 重新编译
make start            # 重启（pm2 注册过则 pm2 restart）
# 或后台实例：make stop-prod PORT=9999 && make start-prod PORT=9999

Docker

make docker-deploy ARGS="--port 9999 --no-build"  # 拉新代码后重新 build
docker compose -f deploy/docker/docker-compose.yml up -d --build

K8s

# 滚动升级（改镜像 tag）
kubectl -n deepthink set image deployment/deepthink-web \
  deepthink=registry.../deepthink-server:v1.2.0
kubectl -n deepthink rollout status deployment/deepthink-web

# 回滚到上一版本
kubectl -n deepthink rollout undo deployment/deepthink-web
kubectl -n deepthink rollout undo deployment/deepthink-web --to-revision=2
kubectl -n deepthink rollout history deployment/deepthink-web  # 查看历史
DB schema 注意：schema 靠 CREATE TABLE IF NOT EXISTS + 代码内置 ALTER 向前演进，向前不兼容旧代码。恢复旧数据备份后必须用最新版后端启动。回滚应用版本时，若新版本已升级 schema，旧代码可能无法启动——务必先回滚数据再回滚应用。

故障排查

现象根因处置
启动报 better-sqlite3 ABI 不匹配Node 升级后原生模块需重编译make 自动探测重编译，或 npm rebuild better-sqlite3
WebSocket 握手失败、卡片不流式误用 bun 运行（不支持 ws upgrade）必须用 node：node dist/index.js，不用 bun
端口被占用旧进程未退make stop 或 make stop-prod PORT=xxxx（SIGTERM→SIGKILL 升级）
pm2 与裸跑抢端口混用两种启动统一用 make start/stop（自动路由 pm2）
桌面版 DMG 启动崩溃 Cannot find better_sqlite3.nodenpm12 allowScripts 拦截 install 脚本见 docs/issues/2026-08-21-desktop-dmg-better-sqlite3-missing.md
K8s 多 Pod 重复处理同一任务waitForTask 曾用 pub/sub（已修）确保使用最新镜像（BRPOP 语义）
K8s trace 文件 Pod 重启丢失trace-io 路径不在 PVC（已修）确保镜像含 DATA_DIR 修复，trace-io 落 /data PVC
backup CronJob 在 PG 模式报错曾用 better-sqlite3 打开不存在的 db（已修）使用最新 backup-cronjob.yaml（postgres:16-alpine 镜像 + pg_dump）
飞书等 IM 不回消息agent-runner 容器未启动 / 凭据未配make status、检查 Web 设置页 IM 配置

桌面应用打包

桌面版 = Electron 壳 + 独立后端 Node 子进程 + HTTP serve 前端（完整复用 Web 应用功能，无内嵌静态文件，安全隔离 contextIsolation:true / nodeIntegration:false）。

打包链路（Makefile）

make desktop-build-deps   # 编译后端+前端+agent-runner（前置）
make desktop-build         # 编译 Electron 壳 TS
make desktop-fetch-node    # 拉取 Node v22.11.0 二进制
make desktop-rebuild-natives  # 用内置 Node ABI 重编译 native（含两道硬校验）

# 各平台打包
make desktop-pack-mac      # macOS arm64 .dmg
make desktop-pack-mac-x64  # macOS x64 .dmg（需 Intel Mac）
make desktop-pack-mac-all  # 双架构
make desktop-pack-win      # Windows .exe (NSIS)
make desktop-pack-linux    # Linux AppImage + .deb
native 模块保障：better-sqlite3 ABI 问题已在打包链路中加两道硬校验（① .node 文件存在 ② 内置 Node 实际 require('better-sqlite3')(':memory:').exec('select 1') 加载验证）。失败即中止打包，绝不会产出残缺 DMG。
